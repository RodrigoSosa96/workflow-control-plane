# Herdr 0.7.5 `agent start` API Update

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task inline.

**Goal:** Update the Workflow launch integration to use the Herdr 0.7.5 `agent start` API (`--kind <KIND> --pane <ID>`), replacing the obsolete `--workspace`/`--tab`/`--split` API that now fails.

**Architecture:** `src/workflow/herdr.js` will issue the new command shape. `src/workflow/execute.js` will prepare the agent pane by splitting the agent tab with the fixture cwd and required workflow env vars, then call `startAgent` with the resulting pane ID and harness kind. Tests and fake Herdr will be updated to match the new contract.

**Tech Stack:** Node.js 24, native `node --test`, Herdr 0.7.5 CLI.

## Global Constraints

- Herdr 0.7.5 `agent start` only accepts `--kind`, `--pane`, `--timeout`, and optional agent argv after `--`.
- `agent start` requires the target pane to be at an interactive shell prompt.
- `pane split` accepts `--cwd`, `--env`, `--direction`, `--ratio`, `--focus`, and can create the pane we need before starting the agent.

### Verified Herdr 0.7.5 contract (observed against the live CLI, 2026-07-24)

- `agent start` has **no** focus flag at all. Both `--focus` and `--no-focus` are rejected with `unknown option`.
- `agent start` types the canonical executable for `--kind` into the pane itself, then appends the
  `AGENT_ARG`s verbatim. Passing the launch argv with its executable produces `pi pi --name ...`,
  so `argv[0]` must be stripped at the adapter boundary.
- `--timeout` must be **greater than** 3000ms and at most 300000ms; `3000` is rejected with
  `invalid_agent_timeout`.
- Herdr writes its JSON error envelope (`{"error":{"code","message"},"id"}`) to **stderr**, leaving
  stdout empty on failure. Parsing only stdout discards the real cause of every failure.
- `pane split --env KEY=VALUE` is repeatable and the variables are present in the new pane's shell.
- Agent names must match `^[a-z][a-z0-9_-]{0,31}$`; an uppercase ticket ID is rejected with
  `invalid_agent_name`. Session names keep their readable casing, so the Herdr name is derived.
- `pane split` returns before the new pane reaches its interactive shell prompt. `agent start`
  rejects an unready pane immediately with `agent_pane_busy` rather than waiting for it, so the
  start has to be retried until the shell is available.
- Workflow env vars must remain allowlisted (`WORKFLOW_RUN_ID`, `WORKFLOW_RUN_DIR`, `WORKFLOW_GENERATION`, `WORKFLOW_HARNESS`, `WORKFLOW_STATE_ROOT`, `WORKFLOW_CONTROL_PLANE_BIN`).
- No destructive cleanup, no real model execution, no Pi/Codex/Claude launch without explicit user approval.

- [ ] **Step 1: Update the signature and command construction**

Replace the `startAgent` implementation so it accepts `paneId`, `kind`, and optional `timeout`, and removes `workspaceId`, `tabId`, `split`, `cwd`, and `env`.

```js
async startAgent({ name, paneId, kind, argv, focus = false, timeout } = {}) {
  if (!Array.isArray(argv) || argv.length === 0 || argv.some((value) => typeof value !== "string" || value.length === 0)) {
    fail("PREFLIGHT", "startAgent requires argv from a trusted source", { name, paneId, kind, argv }, 10);
  }
  if (typeof paneId !== "string" || !paneId) {
    fail("PREFLIGHT", "startAgent requires a pane ID", { name, paneId, kind }, 10);
  }
  if (typeof kind !== "string" || !kind) {
    fail("PREFLIGHT", "startAgent requires an agent kind", { name, paneId, kind }, 10);
  }

  const args = [name];
  pushOption(args, "--kind", kind);
  pushOption(args, "--pane", paneId);
  pushOption(args, "--timeout", timeout);
  pushFocus(args, focus);
  args.push("--", ...argv);

  return normalizeAgentResult(await invoke("agent", "start", args));
}
```
